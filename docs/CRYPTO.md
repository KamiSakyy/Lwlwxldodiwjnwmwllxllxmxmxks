# Протокол MailGram v1

Всё шифрование выполняется на устройстве. «Сервер» — это почтовый ящик Gmail; MailGram не имеет
собственной инфраструктуры, не хранит ключей и не видит открытого текста.

## 1. Идентичность

* Пара ключей **ECDH NIST P-256** создаётся при первом запуске в аппаратном **Android Keystore**
  (`PURPOSE_AGREE_KEY`, alias `mailgram.identity.p256.v1`). Приватный ключ не экспортируется.
* Если устройство не умеет ECDH в Keystore — используется программный ключ, приватная часть которого
  хранится в `SharedPreferences` в зашифрованном виде: **AES-256-GCM**, ключ тоже в Keystore
  (alias `mailgram.box.aes.v1`). Режим показан в настройках («Ключи устройства»).
* Публичный ключ — 65 байт (`0x04 || X || Y`) в base64url. Он не является секретом и публикуется
  в каждом сообщении.

## 2. Вывод ключа сессии

```
sharedSecret = ECDH(мой приватный ключ, публичный ключ собеседника)      // 32 байта
sessionKey   = HKDF-SHA256(
                  ikm  = sharedSecret,
                  salt = "MailGram/v1/salt",
                  info = "MailGram/v1|chat=" + chatUid,
                  L    = 32 )
```

`chatUid` — 8 hex-символов: `SHA-256(lower(min(emailA,emailB)) + "\n" + lower(max(emailA,emailB)))`.
Одинаков у обоих участников и не зависит от порядка адресов. Он же стоит в теме письма.

## 3. Конверт

Тело письма — base64 от JSON-конверта (base64 ради совместимости со всеми почтовыми клиентами):

```json
{
  "v": 1,
  "alg": "EC-P256-ECDH+HKDF-SHA256+ChaCha20-Poly1305",
  "id": "3f8a1c02-6b1e-4b1a-9a11-0d0c7a51f9e2",
  "ts": 1760000000000,
  "chat": "9f2c1ab4",
  "from": "me@gmail.com",
  "to": "friend@gmail.com",
  "pk": "<65 байт публичного ключа отправителя, base64url>",
  "n": "<12-байтовый nonce, base64url>",
  "c": "<шифротекст || 16-байтовый тег Poly1305>"
}
```

* Шифр: **ChaCha20-Poly1305** (RFC 8439), ключ 256 бит, nonce 96 бит, тег 128 бит.
* **AAD** (аутентифицируемые, но не шифруемые данные) — строка:

  ```
  MailGram|1|<id>|<ts>|<from>|<to>|<chat>
  ```

  Любое изменение этих полей (или подмена `id`, `chat`) ломает тег → сообщение отвергается целиком.
* Nonce — 12 случайных байтов из `getrandom()` (модуль C++), ключ сессии уникален для каждого
  направления и диалога; при 96-битном случайном nonce и одном ключе на диалог вероятность коллизии
  пренебрежимо мала для переписки физических лиц.

## 4. Полезная нагрузка (внутри шифротекста)

```json
{"t":"text",  "b":"Привет, мир! 🌍"}
{"t":"image", "b":"<JPEG в base64>", "c":"подпись"}
```

Тип `invite` не шифруется (в нём нет переписки) — это письмо-приглашение с открытым ключом
в служебной строке `X-MailGram-PublicKey: …`.

## 5. Письмо

```
From: me@gmail.com
To: friend@gmail.com
Subject: MailGram 9f2c1ab4
Content-Type: text/plain; charset=UTF-8
Content-Transfer-Encoding: 7bit

eyJ2IjoxLCJhbGciOiJFQy1QMjU2K0hLREYtU0hBMjU2K0NoYUNoYTIwLVBvbHkxMzA1IiwiaWQiOiLigKbigKY=
```

Отправка — `POST /gmail/v1/users/me/messages/send` с полем `raw` (base64url от MIME).
Чтение — `messages.list?q=subject:MailGram newer_than:120d` + `messages.get?format=full`.
Прочитанные сообщения помечаются в Gmail (снимается метка `UNREAD`), чтобы почта и мессенджер
не противоречили друг другу.

## 6. Что защищено, а что нет

| Защищено | Не защищено (видно Google и любому, у кого доступ к ящику) |
|---|---|
| Текст сообщений, подписи, фото | Факт переписки: адреса, время, частота, размер писем |
| Целостность всех полей конверта (AAD + тег) | `MailGram <8-hex>` в теме (псевдоним диалога, не адрес) |
| Невозможность подмены/переигровки сообщения | Метаданные MIME и заголовки письма |

Мы **не** заявляем защиту от анализа трафика: это принципиально невозможно без промежуточного сервера.

## 7. Отпечаток безопасности

`SHA-256("MailGram/v1/safety" || меньшее по байтам из двух ключей || большее)` → 12 групп по 5 цифр
(каждая группа — `(b[2i]<<8 | b[2i+1]) mod 100000`). Сравнив отпечаток голосом или лично, участники
исключают подмену открытого ключа (MITM).

## 8. Реализация крипто-примитивов

Симметричная часть написана вручную на C++17 (`app/src/main/cpp/mailgram_crypto.cpp`) без сторонних
библиотек: SHA-256, HMAC-SHA256, HKDF-SHA256, ChaCha20, Poly1305, AEAD, CSPRNG (`getrandom`/`/dev/urandom`),
затирание секретов в памяти.

Корректность подтверждается тест-векторами RFC:

* SHA-256 — FIPS 180-4 (`SHA-256("abc")`)
* HMAC-SHA256 — RFC 4231, тест-кейс 1
* HKDF-SHA256 — RFC 5869, тест-кейс 1
* Poly1305 — RFC 8439 §2.5.2
* ChaCha20 — RFC 8439 §2.3.2
* **ChaCha20-Poly1305 (AEAD, полный вектор)** — RFC 8439 §2.8.2
* Дополнительно: отказ при подделке шифротекста и AAD, отказ при чужом ключе, обработка 1 МБ данных

Проверки запускаются:
1. в CI (`tools/crypto_selftest.cpp`, обычный `g++` на Ubuntu),
2. в приложении — «Настройки → Безопасность → Проверить шифрование (тест-векторы RFC)».
