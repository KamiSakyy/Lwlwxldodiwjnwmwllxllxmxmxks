# Протокол MailGram: v1 (конверт) и v2 (двойной крысиный шаг)

Документ описывает ровно то, что реализовано в коде: `crypto/MailCrypto.java`, `crypto/Ratchet.java`,
`crypto/RatchetStore.java`, `crypto/Identity.java`, нативное ядро `app/src/main/cpp/`.

## 0. Общая картина

| Слой | Что делает | Где |
|---|---|---|
| Идентичность | пара ключей P-256, приватный ключ в Android Keystore (TEE, экспорт невозможен) | `Identity.java` |
| v1 «конверт» | статический общий секрет ECDH + HKDF + ChaCha20-Poly1305 | `MailCrypto.java` |
| v2 «двойной шаг» | полноценный Double Ratchet: новые DH-ключи на каждый ответ, цепочки ключей сообщений | `Ratchet.java`, `RatchetStore.java` |
| Примитивы | SHA-256, HMAC-SHA256, HKDF-SHA256, ChaCha20-Poly1305, CSPRNG, Curve P-256 | `app/src/main/cpp/mailgram_crypto.cpp` |
| Транспорт | письмо Gmail с темой `MailGram <8 hex id диалога>` | `net/GmailApi.java`, `sync/SyncEngine.java` |

Ключи **никогда** не покидают устройство. В коде нет ни секретов, ни приватных ключей: всё рождается
в Keystore при первом входе.

---

## 1. Идентичность

* Приватный ключ — P-256 (`ECDH`), генерируется в Android Keystore, привязан к устройству.
* Публичный ключ (raw, 65 байт) вкладывается в каждое исходящее письмо и в приглашение.
* Отпечаток безопасности = `SHA-256("MailGram/v1/safety" ‖ ключи, отсортированные по байтам)` →
  12 групп по 5 цифр (60 цифр). Показывается на экране «Сведения о чате» вместе с состоянием
  двойного шага и кнопкой отметки «проверено».

## 2. v1: первый контакт и совместимость

Пока для диалога не поднят сеанс двойного шага (собеседник ещё не прислал свой «шаговый» ключ),
сообщения идут в конверте v1:

```
общий ключ  = HKDF-SHA256( ECDH(мой приватный, публичный собеседника), salt = chatUid, info = "MailGram/v1" )
шифртекст   = ChaCha20-Poly1305(ключ, nonce, AAD = "MailGram/1|id|ts|from|to|chat", полезная нагрузка)
```

Полезная нагрузка — JSON: `t` (тип), `b` (текст или base64 медиа), `m` (MIME), `d` (длительность),
`n`/`s` (имя и размер файла), `r`/`rp` (ответ на сообщение), `w` (волна голосового), `pre` (предключ,
см. ниже), `fwd` (переслано).

## 3. v2: двойной крысиный шаг (Double Ratchet)

Реализация следует спецификации Signal «The Double Ratchet Algorithm» (раздел 5.2), с состояниями
**DHs, DHr, RK, CKs, CKr, Ns, Nr, PN, MKSKIPPED**. Отличия от спецификации — только в примитивах:
DH на P-256 (а не Curve25519) и KDF на HKDF-SHA256.

### 3.1. Начало сеанса (рукопожатие)

Сервера-хранилища предключей нет, поэтому предключ публикуется прямо в приглашении (маркер
`X-MailGram-PreKey:`) и в каждом письме v1 параметром `pre`. Инициатор считает три DH на одном
эфемерном ключе `EK`:

```
инициатор:  DH1 = DH(мой постоянный, постоянный собеседника)
            DH2 = DH(EK, постоянный собеседника)
            DH3 = DH(EK, предключ собеседника)
ответчик:   DH1 = DH(мой постоянный, постоянный собеседника)
            DH2 = DH(мой постоянный, «шаговый» ключ собеседника = EK)
            DH3 = DH(мой предключ, EK)

SK = HKDF-SHA256(DH1 ‖ DH2 ‖ DH3, salt = chatUid, info = "MailGram/DR/x3dh", 32)
```

Дальше обе стороны запускают корневой KDF от `DH3` (инициатор — `dh(EK, pre)`, ответчик — `dh(pre, EK)`:
одно и то же значение): у инициатора появляется цепочка отправки, у ответчика — цепочка приёма.
Ответчик дополнительно генерирует свою новую пару и получает цепочку отправки. Каждый ответ
собеседника с новым публичным DH-ключом запускает `DHRatchet`.

### 3.2. KDF

```
KDF_RK(RK, dh) = HKDF-SHA256(ikm = dh, salt = RK, info = "MailGram/DR/root", 64) → RK′ ‖ CK
KDF_CK(CK):  CK′ = HKDF-SHA256(CK, salt = 0…0 (32 байта), info = "MailGram/DR/chain",   32)
             MK = HKDF-SHA256(CK, salt = 0…0 (32 байта), info = "MailGram/DR/message", 32)
```

Ключ сообщения `MK` (32 байта) → ChaCha20-Poly1305, nonce — случайные 12 байт из заголовка,
AAD = `MailGram/DR|2|id|ts|from|to|chat` ‖ `B64(dh)|pn|n` (все поля заголовка, поэтому подмена ломает тег).

### 3.3. Заголовок v2

```
v=2, alg=…DOUBLE-RATCHET, dh (публичный ключ отправителя), pn (сколько сообщений в прошлой цепочке),
n (номер в текущей цепочке), nc (nonce), c (шифртекст)
```

### 3.4. Пропущенные и отложенные сообщения

* `MAX_SKIP = 500` ключей на одно сообщение, `MAX_SKIPPED_TOTAL = 800` в хранилище;
* ключи отложенных сообщений лежат в `MKSKIPPED` до расшифровки (или до вытеснения);
* использованный ключ удаляется сразу — повторная доставка того же письма не расшифровывается (анти-replay);
* приход нового `dh` означает смену цепочки: сначала пропускаются остатки старой (`PN`), затем шаг DH.

### 3.5. Прямая секретность и пост-компрометация

Каждый ответ собеседника рождает новую пару DH: компромисс текущих ключей не раскрывает прошлые
сообщения (forward secrecy) и автоматически лечится от последующей утечки (post-compromise security) —
это и есть причина, по которой «двойной шаг» считается настоящим сквозным шифрованием, а не «общим
паролем на двоих».

### 3.6. Выход из аккаунта

Сеансы (`RatchetStore`) стираются полностью: `RK`, цепочки, отложенные ключи и предключи. Новый вход —
новое рукопожатие с новым предключем.

## 4. Служебные конверты

Внутри шифротекста ходят управляющие сообщения, которые не отображаются в ленте:

| `t` | Что делает | Поля |
|---|---|---|
| `react` | реакция на сообщение (снятие — `rm=true`) | `mid`, `e`, `rm` |
| `edit` | правка текста | `mid` |
| `del` | удаление у обоих | `mid` |
| `pin` | закрепление и открепление | `mid`, `v` |

## 5. Письмо

```
Тема:   MailGram <8 hex>
Тело:   base64(JSON конверта)     ← единственное, что видно в почте
Адреса: отправитель → получатель  ← метаданные видны всегда (сервера нет)
```

## 6. Что защищено, а что нет

**Защищено.** Содержимое сообщений и вложений; подмена любых полей конверта (AAD); повторная доставка
(удаление использованного ключа); подмена открытого ключа видна через номер безопасности; компрометация
одного сообщения не раскрывает остальные.

**Не защищено.** Метаданные (кто, кому, когда, размер); собеседник, чьё устройство уже взломано;
отсутствие внешнего аудита кода; режим Testing в Google Cloud (refresh-токен живёт 7 дней).

## 7. Проверка

* `tools/simulate_ratchet.py` — симуляция протокола на тех же примитивах (HKDF-SHA256, P-256,
  ChaCha20-Poly1305), повторяющая арифметику `Ratchet.java`: рукопожатие и обмен, шесть раундов смены
  DH-ключей, доставка вне порядка (2/0/1), отказ при подмене заголовка и при испорченном шифртексте,
  отказ при повторной доставке того же письма (анти-replay), отказ при пропуске больше MAX_SKIP.
  Запуск: `python3 tools/simulate_ratchet.py` (нужен пакет `cryptography`).
* Самотест в приложении: «Настройки → Безопасность» прогоняет тест-векторы RFC 8439 / 5869 / 4231 / FIPS 180-4.
* Номер безопасности в карточке чата — 60 цифр из `NativeCrypto.safetyNumber`.

## 8. Реализация примитивов

`app/src/main/cpp/mailgram_crypto.cpp` — SHA-256, HMAC-SHA256, HKDF-SHA256, ChaCha20-Poly1305, CSPRNG
(`getrandom`/`/dev/urandom`), самотест на тест-векторах. Сборка — NDK 28, C++17, `-O2`, без внешних
зависимостей (никаких OpenSSL/BoringSSL: код собран и проверен в этом репозитории).
