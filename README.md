# Web APK Studio

Android-приложение на Java/Kotlin для **офлайн-упаковки статических сайтов в APK** и отдельного режима с **встроенным Python/Flask сервером**, отображаемым в Android WebView.

## Возможности

- выбрать один `index.html` или ZIP-проект с `index.html`, CSS, JavaScript, изображениями и другими локальными файлами;
- переключиться на отдельный Python/Flask профиль: APK с Python 3.10 запускает встроенный `server (13).py` и показывает интерфейс в том же Android WebView;
- задать имя приложения и Android package ID, например `com.company.mysite`;
- выбрать фото для иконки: оно автоматически кадрируется, превращается в заполненный круг и подготавливается для всех пяти плотностей Android; в APK круглая иконка назначается также как `roundIcon`;
- перед сборкой включить автоповорот и/или полноэкранный режим; системные статусная и навигационная панели в обычном режиме прозрачны;
- подписывать и конвертер, и каждый созданный APK одним постоянным RSA-ключом из `handoff/`;
- сохранять новые версии созданного приложения с увеличенным `versionCode`, чтобы Android устанавливал их обновлением;
- установить созданный APK прямо из приложения через системный установщик Android или сохранить его через выбор файлов; если Android требует разрешение на установку из неизвестных источников, конвертер откроет нужную системную настройку;
- восстанавливать выбранный проект, имя, package ID, версию и параметры после перезапуска; выбранный сайт можно очистить одной кнопкой;
- показывать ход подготовки, шифрования и подписи APK, не выводя имена файлов проекта;
- запускать созданное приложение с экраном загрузки под выбранным названием и своей иконкой (либо нейтральной иконкой по умолчанию); при ошибке стартовой страницы доступна кнопка повтора;
- собирать сам Web APK Studio в **GitHub Actions**; workflow проверяет подписи и прогоняет многомегабайтный smoke-тест генератора.

## Офлайн-сборка сайта на телефоне

После установки Web APK Studio интернет не нужен. Приложение распаковывает локальные исходники в APK-шаблон с Android `WebView`, меняет package ID и название, пересоздаёт иконки, подписывает APK и предлагает сохранить его. Android SDK/Gradle на телефоне не устанавливаются и не скачиваются.

Для ZIP положите `index.html` в корень либо в одну верхнюю папку архива. Если внутри несколько стартовых HTML-файлов, поместите один `index.html` в корень сайта. Одиночный HTML импортируется как `index.html`; отдельные CSS/JS/изображения для него можно добавить через ZIP.

Исходники сайта в APK не лежат открытыми файлами: содержимое каждого файла шифруется AES-256-GCM со случайным nonce, затем шифротекст и зашифрованная карта путей упаковываются в ZIP-контейнер `assets/a.c`. Имена файлов внутри контейнера заменены на короткие идентификаторы. WebView получает ресурсы через потоковую расшифровку в памяти; исходный сайт не распаковывается в открытом виде на диск.

Конвертер и шаблон сайта минифицируются R8 в полном режиме с оптимизирующими ProGuard-правилами; native-бинарь компилируется с оптимизацией, скрытием символов и stripping. Для каждого ABI APK содержит ровно один native-файл — `libc++_shared.so`; поддерживаются только ARMv7 (`armeabi-v7a`) и ARM64 (`arm64-v8a`). Это наш собственный JNI-модуль с статически включённым NDK C++ runtime, а не оригинальный prebuilt-файл runtime. Такая обфускация повышает стоимость анализа, но не исключает реверс-инжиниринг: ключ, нужный приложению офлайн, технически можно извлечь из исполняемой среды.

Сайт открывается из зашифрованного APK-контейнера. JavaScript включён; Android WebView использует установленный на устройстве системный движок. У приложения сайта нет разрешения на интернет: удалённые CDN, API, шрифты и URL не будут работать офлайн — сохраните необходимые файлы внутри ZIP.

Стартовый экран собранного APK использует выбранное название и иконку пользователя (либо нейтральную иконку по умолчанию) и не показывает бренд конвертера. Это только white-label оформление: созданное приложение по-прежнему отображает сайт в Android WebView, и его техническую архитектуру можно определить анализом APK. Оно не маскируется под нативное приложение и не скрывает своё поведение от анализа.

## Встроенный Python/Flask режим

Переключатель **Python / Flask** собирает отдельный тип APK и не меняет обычную сборку статического сайта. Внутри Python-варианта находится Chaquopy runtime (Python 3.10), Flask, Requests и копия `server (13).py`; сервер стартует внутри процесса приложения на случайном порту `127.0.0.1`, а Android WebView открывает `http://127.0.0.1:<port>/`. Сервер не слушает LAN-интерфейсы. API-запросы локального интерфейса защищены случайным токеном процесса. Сборка Python-APK требует Android 7.0/API 24 или новее и включает ARMv7/ARM64 runtime; APK значительно крупнее статического варианта, а первый запуск может занять дольше.

В этом режиме включено Android-разрешение `INTERNET`, так как предоставленный код обращается к VK API. Это разрешение отсутствует в статическом WebView APK. Для записи голосовых сообщений и видео WebView может запросить системные разрешения на микрофон и камеру. Отсутствующий модуль `cloud.cloud_bp` заменён отключённым blueprint, который отвечает HTTP 501. Firebase также выключен: URL базы и API key принудительно пустые, а файл ключей приложения сохраняется только в приватной папке APK. Поэтому cloud/Firebase функции исходника не работают; внешние API VK по-прежнему требуют соединения и действующей конфигурации/токенов. Python-файлы включены в APK runtime и не являются защищённым или криптографически скрытым хранилищем исходного кода.

Этот профиль собирает именно встроенный экземпляр `server (13).py`, а не произвольный пользовательский Flask-проект: импорт проекта на телефоне и установка дополнительных Python-пакетов в UI не предусмотрены. GitHub Actions собирает оба runtime-шаблона, проверяет включение Chaquopy и сохраняет прежний smoke-тест статических сайт-APK.

## Размер статического проекта и APK

Для исходников статического сайта, создаваемого сайт-APK и самого Web APK Studio нет искусственного лимита размера. ZIP и одиночный HTML копируются потоком, поэтому большие проекты не загружаются целиком в память. Практические пределы сайта — свободное место на устройстве, число файлов (до 10 000), ZIP32 (ZIP64 пока не поддерживается; предел формата — около 4 ГБ) и ограничения файловой системы.

## Постоянная подпись и обновления

Конвертер и все создаваемые сайт-APK подписываются одним и тем же постоянным RSA-ключом `handoff/WebAPK-Studio-signing.p12`. SHA-256 fingerprint сертификата: `0D:7E:18:92:DD:D4:47:F4:21:E2:2C:E2:7C:0D:E3:58:4A:6B:4A:AC:50:61:B1:67:67:6C:18:58:E1:65:1F:27`. При одинаковом package ID генератор автоматически повышает `versionCode`, поэтому свежая сборка устанавливается поверх предыдущей. APK подписывается схемами JAR/v1 и APK Signature Scheme v2; GitHub Actions проверяет обе через Android `apksigner`.

Опубликованные [APK конвертера](https://github.com/KamiSakyy/Lwlwxldodiwjnwmwllxllxmxmxks/blob/arena/01a10cb3-lwlwxldodiwjnwmwllxllxmxmxks/dist/WebAPK-Studio.apk?raw=true) и [исходный ZIP](https://github.com/KamiSakyy/Lwlwxldodiwjnwmwllxllxmxmxks/blob/arena/01a10cb3-lwlwxldodiwjnwmwllxllxmxmxks/dist/WebAPK-Studio-source.zip?raw=true) публикуются в GitHub-ветке; те же файлы доступны в [артефактах сборки GitHub Actions](https://github.com/KamiSakyy/Lwlwxldodiwjnwmwllxllxmxmxks/actions/workflows/android.yml).

**По прямому требованию владельца ключевой файл и его пароль лежат в публичном handoff/репозитории. Это небезопасно:** любой скачавший исходники сможет подписать поддельное обновление для любого приложения, созданного этим конвертером. Не используйте такую сборку для конфиденциальных или магазинных приложений.

**Одноразовая миграция:** ранее опубликованные версии конвертера и созданные ими APK подписаны другими ключами. Android не позволит заменить их новым сертификатом. Старые приложения нужно удалить и установить заново; следующие обновления будут работать с постоянным handoff-ключом. Созданные APK по умолчанию портретные, с прозрачными системными панелями; автоповорот и полноэкранный режим включаются перед сборкой соответствующими переключателями.

## Сборка APK через GitHub Actions

В `.github/workflows/android.yml` настроена сборка **только для ветки Arena этой сессии** и ручной запуск `workflow_dispatch`. Keystore и открытый пароль читаются из `handoff/signing.properties`; Actions Secrets не используются. Workflow собирает конвертер, статический WebView-шаблон и Python/Flask-шаблон; проверяет общую v1/v2-подпись, версию APK, автоповорот, fullscreen-настройку, все плотности иконки, smoke APK статического режима и наличие Chaquopy runtime в Python-варианте. APK и исходный ZIP публикуются как артефакты Actions и в `dist/` ветки.
