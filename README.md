# Web APK Studio

Небольшое Android-приложение на Java для **полностью офлайн-упаковки сайта в настоящий устанавливаемый APK**.

## Возможности

- выбрать один `index.html` или ZIP-проект с `index.html`, CSS, JavaScript, изображениями и другими локальными файлами;
- задать имя приложения и Android package ID, например `com.company.mysite`;
- выбрать собственную картинку-иконку;
- получить подписанный APK и сохранить его через системный выбор файлов;
- собирать сам Web APK Studio в **GitHub Actions**: его APK сохраняется в пределах 1 000 000 байт, а workflow проверяет подписи и прогоняет многомегабайтный smoke-тест генератора.

## Офлайн-сборка сайта на телефоне

После установки Web APK Studio интернет не нужен. Приложение распаковывает локальные исходники в APK-шаблон с Android `WebView`, меняет package ID и название, пересоздаёт иконки, подписывает APK и предлагает сохранить его. Android SDK/Gradle на телефоне не устанавливаются и не скачиваются.

Для ZIP положите `index.html` в корень либо в одну верхнюю папку архива. Если внутри несколько стартовых HTML-файлов, поместите один `index.html` в корень сайта. Одиночный HTML импортируется как `index.html`; отдельные CSS/JS/изображения для него можно добавить через ZIP.

Сайт открывается из локальных APK assets. JavaScript включён; Android WebView использует установленный на устройстве системный движок. У приложения сайта нет разрешения на интернет: удалённые CDN, API, шрифты и URL не будут работать офлайн — сохраните необходимые файлы внутри ZIP.

## Размер проекта и APK

Для исходников сайта и создаваемого сайт-APK нет искусственного лимита 1 МБ или 50 МБ. ZIP и одиночный HTML копируются потоком, поэтому большие проекты не загружаются целиком в память. Практические пределы — свободное место на устройстве, число файлов (до 10 000), ZIP32 (ZIP64 пока не поддерживается; предел формата — около 4 ГБ) и ограничения файловой системы. Отдельно, APK самого Web APK Studio по-прежнему удерживается в пределах 1 000 000 байт.

## Подпись созданных APK

Каждая установка генератора создаёт отдельный RSA-ключ подписи в закрытой папке приложения и использует его повторно, чтобы APK с тем же package ID можно было обновлять этой же установкой генератора. Не очищайте данные и не удаляйте Web APK Studio, если хотите сохранить возможность подписывать обновления тем же ключом. Этот ключ не экспортируется и не восстанавливается после переустановки приложения. APK получает JAR/v1 для совместимости со старыми Android и APK Signature Scheme v2 для современных версий; подпись проверяется в GitHub Actions через Android `apksigner`.

APK самого Web APK Studio в Actions подписывается временным debug-ключом CI для тестовой установки. Для публикации в магазине приложение нужно подписать своим release-ключом.

## Сборка APK через GitHub Actions

В `.github/workflows/android.yml` настроена сборка **только для ветки Arena этой сессии** и ручной запуск `workflow_dispatch`. Workflow:

1. устанавливает Java 17, Gradle 8.9 и Android SDK 35;
2. собирает `:app:assembleRelease`, включая Android-шаблон для будущих офлайн-сборок;
3. создаёт чистый архив исходников;
4. удерживает APK самого Web APK Studio в пределах 1 000 000 байт, проверяет подписи через Android `apksigner` и тестирует APK сайта размером более 3 МБ;
5. сохраняет `dist/WebAPK-Studio.apk` и `dist/WebAPK-Studio-source.zip` в ветке и публикует их как артефакты запуска Actions.

Исходный проект также можно собрать из Android Studio с Android SDK 35 и Gradle 8.9.
