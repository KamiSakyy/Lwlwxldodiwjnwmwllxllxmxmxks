# MailGram — мессенджер на вашей почте Gmail

**Сквозной (end-to-end) шифрованный мессенджер, который не использует серверы.** Транспорт — ваш
собственный ящик Gmail: сообщение шифруется на телефоне, уходит письмом самому себе и собеседнику,
и расшифровывается только на устройствах участников.

## Что уже работает

| Возможность | Как сделано |
|---|---|
| **Вход через Google в один тап** | OAuth 2.0 Authorization Code + PKCE (RFC 7636), Chrome Custom Tabs, без сервера |
| **Сквозное шифрование** | ECDH P-256 (ключи в аппаратном Android Keystore) + HKDF-SHA256 + ChaCha20-Poly1305 (RFC 8439) |
| **Транспорт без серверов** | Gmail REST API (`gmail.modify`): чтение писем, отправка, снятие метки «непрочитано» |
| **Мессенджер «как Telegram»** | список чатов с аватарами и счётчиками, пузыри с датами, статусы ✓/«отправляется»/ошибка, лента, эмодзи, фото |
| **Мгновенная доставка** | фоновая служба синхронизации (опрос почты каждые 10–300 с) + опрос каждые 7 с в открытом чате |
| **Уведомления с быстрым ответом** | MessagingStyle + RemoteInput: ответить можно прямо из шторки |
| **Тёмная/светлая тема, Material 3** | `Theme.Material3.DayNight`, акцент #3390EC, свои цвета пузырей |
| **Проверка шифрования** | экран «Настройки → Безопасность» прогоняет тест-векторы RFC прямо в приложении |
| **Отпечаток безопасности** | 12 групп цифр (SHA-256 по паре открытых ключей) — защита от подмены ключа |
| **Свои ключи** | по умолчанию ключ рождается в Keystore и не покидает устройство; есть программный резерв под ключом Keystore |
| **Нет ключей и секретов в коде** | client ID берётся из GitHub Secret при сборке **или** вводится в приложении; токены шифруются ключом Keystore |

Стек: **Kotlin не нужен** — Android на **Java 17** + **C++17** (NDK), Material 3, AppCompat, RecyclerView,
Chrome Custom Tabs. AGP 9.4, Gradle 9.6, `compileSdk`/`targetSdk` 37 (Android 17), `minSdk` 26 (Android 8.0).

## Как это устроено (кратко)

1. **Ключи.** При первом входе устройство создаёт пару ключей ECDH на кривой P-256. Приватный ключ
   живёт в аппаратном Android Keystore (TEE), экспорт невозможен.
2. **Общий секрет.** Для диалога ключ сессии считается так:
   `HKDF-SHA256( ECDH(мой приватный, публичный собеседника), salt="MailGram/v1/salt", info="MailGram/v1|chat=<id>" )`.
3. **Конверт.** Сообщение шифруется ChaCha20-Poly1305, где AAD — заголовочные поля конверта
   (версия, id, время, от/кому, id диалога). Подмена любого поля ломает тег → расшифровка невозможна.
4. **Письмо.** Конверт (JSON) кодируется в base64 и уходит письмом с темой `MailGram <8-hex id диалога>`.
   Тема и адреса — единственные метаданные, которые видит почта.
5. **Публичный ключ** отправителя вложен в каждый конверт (65 байт), поэтому собеседник всегда может
   ответить уже зашифрованным сообщением.

Подробности — [docs/CRYPTO.md](docs/CRYPTO.md).

### Первое сообщение новому собеседнику

Пока у собеседника нет ключа, шифровать нечем (это честная особенность любой E2E-системы без серверов).
Поэтому первое письмо — **приглашение**: ваши имя, ваш публичный ключ, ссылка на APK. В нём **нет
переписки**, а в интерфейсе он помечен как «Приглашение». Как только собеседник ответит, чат переходит
в режим «🔒 сквозное шифрование», и всё дальнейшее — только шифротекст.

## Сборка APK (то, что вы просили: только GitHub Actions, без локальной машины)

1. Откройте вкладку **Actions** → workflow **«MailGram — сборка APK»** → **Run workflow**
   (либо просто запушьте коммит — сборка стартует сама).
2. Дождитесь трёх зелёных задач:
   * `Крипто-ядро C++ (тест-векторы RFC)` — компилирует `mailgram_crypto.cpp` на хосте и прогоняет
     векторы RFC 8439 / RFC 5869 / RFC 4231 / FIPS 180-4: доказательство, что шифрование настоящее;
   * `Проверка компиляции (Java + ресурсы)`;
   * `Сборка APK (Java + C++)`.
3. Скачайте APK:
   * из артефакта сборки (**Actions → последний запуск → Artifacts → MailGram-APK**), или
   * по постоянной ссылке: **https://github.com/KamiSakyy/Lwlwxldodiwjnwmwllxllxmxmxks/releases/tag/apk-latest** → `app-release.apk`.
4. Установите на Android 8.0+ (разрешите установку из неизвестных источников).

Что печатает сборка в логе (эти данные нужны для Google Cloud):

```
Размер APK: ~4 МБ (лимит 15 МБ проверяется автоматически)
=== SHA-1 подписи (вставить в Google Cloud Console) ===
sha1: BA:CF:61:D8:5B:A6:51:0E:27:6B:3C:8D:B8:79:43:0A:51:83:47:32
```

Подпись release-сборки — из файла `keystore/mailgram-dev.p12` (пароль `mailgram`, alias `mailgram`).
Хотите свою подпись — создайте keystore и передайте в сборку секреты
`MAILGRAM_STORE_FILE`, `MAILGRAM_STORE_PASSWORD`, `MAILGRAM_KEY_ALIAS`
(или параметры `-Pmailgram.storeFile=...`). После смены подписи **обязательно** обновите SHA-1 в консоли Google.

## Подключение входа через Google (5 минут, один раз)

Приложению нужен **ваш** OAuth client ID: это не секрет (публичный клиент), но Google требует, чтобы
client был вашим. Внутри приложения есть экран-помощник: **«Настройка подключения»** — он показывает имя
пакета, SHA-1 и redirect URI и принимает client ID.

1. <https://console.cloud.google.com/> → создайте проект.
2. **APIs & Services → Library** → включите **Gmail API**.
3. **OAuth consent screen** → тип **External**, заполните название; в разделе **Test users**
   добавьте свой Gmail. (Приложение не верифицировано Google, поэтому работает в режиме тестирования —
   это нормально для личного использования; при желании можно пройти верификацию.)
4. **Credentials → Create credentials → OAuth client ID → Android**:
   * *Package name*: `com.mailgram.app`
   * *SHA-1*: `BA:CF:61:D8:5B:A6:51:0E:27:6B:3C:8D:B8:79:43:0A:51:83:47:32` (или свой, см. ниже)
5. Скопируйте **client ID** и:
   * **Вариант А (вход «из коробки»):** добавьте его в GitHub → Settings → Secrets and variables →
     Actions → New secret с именем `OAUTH_CLIENT_ID` и пересоберите APK — вход в один тап, без настройки;
   * **Вариант Б (без пересборки):** вставьте client ID в приложении на экране «Настройка подключения»
     и выберите тип клиента **«Desktop + локальный порт»** — тогда в консоли нужно создать ещё один
     OAuth-клиент типа *Desktop* и добавить redirect URI `http://127.0.0.1:7717/oauth2redirect`.

Пошагово и с решением типичных ошибок — [docs/OAUTH_SETUP.md](docs/OAUTH_SETUP.md).

## Честные ограничения

* **Почта видит метаданные**: кто кому писал, когда, размер письма и `MailGram <id диалога>` в теме.
  Никакого сервера в схеме нет, поэтому скрывать метаданные от Google невозможно в принципе.
* **Вложения** — сжатые фото до ~0.9 МБ (ограничение почтового протокола и разумный размер APK);
  другие типы файлов и голосовые сообщения — в планах.
* **Одно устройство — одна идентичность.** Ключ живёт в Keystore, поэтому на втором телефоне будет
  свой ключ; собеседник увидит вторую идентичность в том же чате (расшифровка работает, но отпечаток
  безопасности будет другим). Мультиустройство — следующий шаг.
* **Нет «онлайн/печатает»**: без сервера для этого понадобились бы служебные письма на каждое событие.
* **«Приходит сразу» — это до 4 секунд, а не мгновенно.** В открытом чате приложение спрашивает
  почту каждые 4 секунды (и сразу при входе в чат), в фоне — каждые 30 секунд, а если Android выгрузил
  службу — раз в 15 минут по будильнику. Без своего сервера и без Gmail `users.watch` / Pub-Sub
  (они требуют серверную часть) «пуш» на устройство устроить нельзя — только опрос.
* **Первый контакт требует ответа собеседника**: ваше приглашение несёт публичный ключ, но пока
  собеседник не ответит, шифровать вам нечем — до его первого письма кнопка отправки ждёт.
* **Лимиты Gmail:** квота API (миллионы единиц в сутки — для личного использования незаметно) и
  ограничение на 6 часов непрерывной фоновой службы на Android 15+; после этого синхронизация
  продолжается редкими пробуждениями (раз в 15 минут) и мгновенно — при открытии приложения.
* **Не для секретов государственной важности**: код открыт, но не проходил внешний аудит.
